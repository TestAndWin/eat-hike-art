# Document Learnings

Review the current conversation and identify any lessons learned, patterns discovered, or important technical decisions that should be documented.

## Tasks

1. **Analyze the conversation** for:
   - Bug fixes and their root causes
   - New dependencies or configurations added
   - Patterns or conventions established
   - Technical decisions made
   - Workarounds or gotchas discovered

2. **Suggest documentation updates** for:
   - `CLAUDE.md` - Project instructions and guidelines
   - `docs/TECH_STACK.md` - Technical dependencies and configurations
   - `docs/DOMAIN_MODEL.md` - Data model changes
   - ADRs in `docs/adr/` - Architecture decisions

3. **Present findings** as:
   - A brief summary of what was learned
   - Specific suggestions for which file(s) to update
   - Example content to add

4. **Ask for confirmation** before making any changes.

## Output Format

```
## Learnings from this Session

### [Topic 1]
- What was learned
- Suggested file: `path/to/file.md`
- Content to add: ...

### [Topic 2]
...

---
Which of these should I document?
```
